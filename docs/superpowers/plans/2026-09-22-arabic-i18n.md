# Arabic Language Support Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The Emara Academy site is fully usable in Arabic — locale-prefixed routing (`/ar/...`), a right-to-left mirrored layout, hand-written accurate Arabic copy on every static page, and bilingual (English/Arabic) fields for admin-managed programs, events, and classes.

**Architecture:** `next-intl` provides locale routing and message catalogs; the existing `app/(site)/...` route group becomes `app/[locale]/...`. RTL is achieved by converting `app/globals.css` from physical to logical CSS properties so the existing stylesheet mirrors automatically under `dir="rtl"`, with a handful of `[dir="rtl"]`-scoped overrides for the few places (flex row order, icon direction) logical properties don't cover. `programs`/`events`/`classes` gain nullable `_ar` columns; admin forms grow an English/Arabic tab; public pages read the `_ar` field with English fallback.

**Tech Stack:** Next.js 16 (App Router), TypeScript, `next-intl`, Supabase (Postgres), existing custom CSS (no Tailwind utility usage in the touched files).

**Spec:** [docs/superpowers/specs/2026-09-22-arabic-i18n-design.md](../specs/2026-09-22-arabic-i18n-design.md)

## Global Constraints

- No merge to `main` and no `git push` to a remote that triggers a production deploy — all work stays on the `arabic-i18n` branch until the owner explicitly approves going live.
- English site behavior, URLs, and admin panel must be unchanged for existing users — this is additive.
- Admin panel UI chrome (labels, nav, buttons) stays English-only; only content *fields* gain an Arabic option.
- Arabic translation is hand-written for accuracy and register (formal, warm, matches the manuscript aesthetic and the Arabic already on the site) — never a literal/mechanical word-for-word rendering.
- Arabic DB fields are optional; a missing `_ar` value falls back to the English value on the Arabic site, never a blank or an error.
- This codebase has no automated test runner — "verify" in every task means `npm run build` (must stay clean) + `npx eslint .` (must stay clean) + a manual check in the browser preview, matching how every prior change in this project has been verified.

## Review Focus

- A page visited in Arabic before its translation task has run (i.e., mid-rollout) must still render — Stage 1 ships the routing/RTL/build machinery with the *English* strings still in place under `/ar`, so at every commit the site is in a working state, never a half-translated crash.
- An admin editing a program/event/class and leaving every Arabic field blank must produce a normal-looking Arabic-locale page (English fallback), not an empty title or a literal `null`/`undefined` rendered as text.
- The events calendar grid and the programs bookshelf (3D flip cards) are the two most complex layouts on the site — both must be checked by eye under `dir="rtl"`, not assumed correct from the CSS conversion alone.
- `next-intl`'s locale-prefix middleware must not intercept `/admin/*` — admin must work identically, unauthenticated-redirect included, after routing changes land.
- Long-form legal text (the three policy pages) is exactly the content most likely to still contain an untranslated English leftover if a section is skipped — each policy task explicitly enumerates every section it must translate so none are silently missed.

## File Structure

**New:**
- `messages/en.json`, `messages/ar.json` — next-intl message catalogs, namespaced by page.
- `i18n/routing.ts` — next-intl's locale list + routing config.
- `i18n/request.ts` — next-intl's server-side request config (loads the right message file).
- `app/[locale]/layout.tsx` — replaces the chrome currently in `app/(site)/layout.tsx`; sets `dir`/`lang`.
- `supabase/migrations/005_arabic_content.sql` — `_ar` columns.
- `lib/i18nDisplay.ts` — small lookup tables for translating structured-but-not-prose values (city names, day names, etc.) used by both public pages and (read-only) admin previews.

**Moved** (git mv, then edited for i18n): every file currently under `app/(site)/` moves to `app/[locale]/`, same relative structure (e.g. `app/(site)/about/page.tsx` → `app/[locale]/about/page.tsx`). `app/(site)/layout.tsx` is deleted; its chrome logic merges into `app/[locale]/layout.tsx`.

**Modified:**
- `proxy.ts` — compose next-intl middleware with the existing admin-auth logic.
- `next.config.ts` — wrap with `next-intl`'s plugin.
- `components/TopBar.tsx`, `components/Footer.tsx`, `components/LangSwitcher.tsx` — locale-aware links, real AR wiring.
- `app/globals.css` — physical → logical property conversion, `[dir="rtl"]` overrides for the known trouble spots.
- `app/admin/(dashboard)/programs/page.tsx`, `components/admin/EventsAdmin.tsx`, `components/admin/ClassesAdmin.tsx`, `app/admin/actions.ts` — Arabic tab + fields.
- `components/ProgramShelf.tsx`, `app/[locale]/programs/[slug]/page.tsx`, `components/EventsBoard.tsx`, `components/ClassesBoard.tsx` — read `_ar` fields with fallback, once locale-aware.

- [ ] **Step 4:** Add next-intl's middleware to `proxy.ts`, composed with the existing admin-auth check (they guard disjoint path prefixes, so run next-intl's middleware first and let it pass through for `/admin` paths since its matcher won't include them):

```ts
import { createServerClient } from "@supabase/ssr";
import { NextResponse, type NextRequest } from "next/server";
import createIntlMiddleware from "next-intl/middleware";
import { routing } from "@/i18n/routing";

const intlMiddleware = createIntlMiddleware(routing);

// Temporarily off while the Supabase project is paused (billing) and there's
// no admin login to test against yet — the owner asked to see the admin UI
// without the password gate for now. Flip back to true once the Supabase
// project is unpaused and the admin@emaraacademy.org user exists.
const ADMIN_AUTH_ENABLED = false;

export async function proxy(request: NextRequest) {
  if (request.nextUrl.pathname.startsWith("/admin")) {
    if (!ADMIN_AUTH_ENABLED) return NextResponse.next();
    return adminAuthCheck(request);
  }
  return intlMiddleware(request);
}

async function adminAuthCheck(request: NextRequest) {
  let response = NextResponse.next({ request });

  const supabase = createServerClient(
    process.env.NEXT_PUBLIC_SUPABASE_URL!,
    process.env.NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY!,
    {
      cookies: {
        getAll() {
          return request.cookies.getAll();
        },
        setAll(cookiesToSet) {
          cookiesToSet.forEach(({ name, value }) => request.cookies.set(name, value));
          response = NextResponse.next({ request });
          cookiesToSet.forEach(({ name, value, options }) =>
            response.cookies.set(name, value, options)
          );
        },
      },
    }
  );

  const {
    data: { user },
  } = await supabase.auth.getUser();

  const isLoginPage = request.nextUrl.pathname === "/admin/login";

  if (!user && !isLoginPage) {
    const url = request.nextUrl.clone();
    url.pathname = "/admin/login";
    return NextResponse.redirect(url);
  }
  if (user && isLoginPage) {
    const url = request.nextUrl.clone();
    url.pathname = "/admin";
    return NextResponse.redirect(url);
  }

  return response;
}

export const config = {
  matcher: ["/admin/:path*", "/((?!api|_next|_vercel|.*\\..*).*)"],
};
```

- [ ] **Step 2:** Replace the disabled AR button in `components/LangSwitcher.tsx` with a real locale-switch link, keeping ES disabled exactly as today:

```tsx
"use client";

import { useEffect, useRef, useState } from "react";
import { useLocale } from "next-intl";
import { Link, usePathname } from "@/i18n/routing";

const LANGS = [
  { code: "en", label: "English", ready: true },
  { code: "es", label: "Español", ready: false },
  { code: "ar", label: "العربية", ready: true },
];

export default function LangSwitcher() {
  const [open, setOpen] = useState(false);
  const ref = useRef<HTMLDivElement>(null);
  const locale = useLocale();
  const pathname = usePathname();

  useEffect(() => {
    if (!open) return;
    const onClick = (e: MouseEvent) => {
      if (ref.current && !ref.current.contains(e.target as Node)) setOpen(false);
    };
    const onKey = (e: KeyboardEvent) => {
      if (e.key === "Escape") setOpen(false);
    };
    document.addEventListener("mousedown", onClick);
    document.addEventListener("keydown", onKey);
    return () => {
      document.removeEventListener("mousedown", onClick);
      document.removeEventListener("keydown", onKey);
    };
  }, [open]);

  return (
    <div className="lang-switcher" ref={ref}>
      <button
        type="button"
        className="lang-btn"
        aria-haspopup="listbox"
        aria-expanded={open}
        aria-label="Change language"
        onClick={() => setOpen(!open)}
      >
        {locale.toUpperCase()}
      </button>
      {open && (
        <div className="lang-menu" role="listbox" aria-label="Languages">
          {LANGS.map((l) =>
            l.ready ? (
              <Link
                key={l.code}
                href={pathname}
                locale={l.code}
                role="option"
                aria-selected={l.code === locale}
                className={`lang-option ${l.code === locale ? "active" : ""}`}
                onClick={() => setOpen(false)}
              >
                <span>{l.label}</span>
              </Link>
            ) : (
              <button
                key={l.code}
                type="button"
                role="option"
                aria-selected={false}
                className="lang-option"
                disabled
              >
                <span>{l.label}</span>
                <span className="lang-soon">soon</span>
              </button>
            )
          )}
        </div>
      )}
    </div>
  );
}
```

const CITY_AR: Record<string, string> = {
  "Playa del Carmen": "بلايا ديل كارمن",
  "Cancún": "كانكون",
  "Online": "عبر الإنترنت",

const DAY_AR: Record<string, string> = {
  Sundays: "الأحد",

  Tuesdays: "الثلاثاء",
  Wednesdays: "الأربعاء",
  Thursdays: "الخميس",
  Fridays: "الجمعة",
  Saturdays: "السبت",
};

export function translateCity(city: string, locale: string): string {
  if (locale !== "ar") return city;
  return CITY_AR[city] ?? city;
}

export function translateDay(day: string, locale: string): string {
  if (locale !== "ar") return day;
  return DAY_AR[day] ?? day;
}
